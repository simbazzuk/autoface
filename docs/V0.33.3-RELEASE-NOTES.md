# AutoFace v0.33.3 — Discovery Resilience

Fixes a Discovery failure seen when Firestore contains a member/test profile whose Firebase Authentication user has been removed.

## Changes
- Candidate Authentication `user-not-found` records are skipped rather than crashing the entire Discovery request.
- The requesting member is treated differently: if their signed-in UID no longer has a Firebase Authentication user, the API returns a structured `ACCOUNT_RECORD_MISSING` error.
- Discover no longer misrepresents API/account failures as an incomplete Atlas/readiness journey.
- Account-record errors have a dedicated recovery state and explain that Profile, Atlas and preference data were not modified.
- Test accounts can see how many stale records were ignored during curation.
- Reviewed recommendations and recommendation detail use strict requester-account handling as well.

No Firestore rule changes or new collections are required.
