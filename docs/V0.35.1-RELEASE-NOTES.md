# AutoFace v0.35.1 — Camera diagnostics

## What changed

- Adds a browser camera pre-flight test before AWS Face Liveness starts.
- Reports the selected camera label, negotiated video resolution and frame rate when available.
- Maps common browser camera failures such as `NotAllowedError`, `NotFoundError`, `NotReadableError`, `OverconstrainedError` and `SecurityError` into useful guidance.
- Stops the diagnostic stream and waits briefly before AWS Amplify opens the webcam, reducing camera-lock contention on Windows.
- Adds a standalone **Test camera** action so camera access can be checked independently of AWS/Cognito/Rekognition.
- Improves AWS liveness error text so a passing camera pre-flight can distinguish browser/device problems from AWS-session problems.

## Test path

1. Sign in and open `/verify-face`.
2. Select **Test camera**.
3. Confirm **Camera ready** and note the detected device/video settings.
4. Select **Verify my face**. AutoFace repeats the pre-flight, releases the stream, and then starts AWS Face Liveness.
5. If the pre-flight passes but AWS still shows a camera/session error, capture the AutoFace message and browser console/Vercel logs for the next diagnostic step.

No Firebase authentication, profile, matching or Atlas behaviour is changed by this patch.
