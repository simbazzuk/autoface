# AutoFace v0.35.0 — AWS Face Verification Foundation

## Purpose
Introduces the first production-provider foundation for a **Face Verified** trust signal using Amazon Rekognition. The flow is intentionally separate from Firebase authentication and from AutoFace matchmaking.

## Added
- `/verify-face` member journey with AWS Amplify Face Liveness UI.
- `POST /api/face-verification/start` creates a Rekognition liveness session.
- `POST /api/face-verification/result` retrieves liveness results and performs a 1:1 `CompareFaces` call against the member's AutoFace profile photo.
- Firestore `faceVerificationSessions` audit records.
- `identity.faceVerified`, `identity.photoVerified`, `identity.livenessVerified` trust signals after both checks pass.
- Security-event records for start, success and failed attempts.
- AWS/Cognito environment variable placeholders in `.env.example`.
- Navigation now surfaces **Face Verification** rather than the earlier generic Photo Verification entry.

## Privacy boundary
v0.35.0 does **not** create a Rekognition Face Collection and does not provide member-to-member face search. Rekognition is used for a one-to-one verification step. The public AutoFace UI only receives a verification result; confidence values are shown only to the member on the result page during this foundation phase.

## AWS setup required
The build intentionally ships disabled until AWS is configured. Configure:

- `AWS_REGION`
- `AWS_ACCESS_KEY_ID`
- `AWS_SECRET_ACCESS_KEY`
- `NEXT_PUBLIC_AWS_REGION`
- `NEXT_PUBLIC_AWS_COGNITO_IDENTITY_POOL_ID`

The server IAM identity requires least-privilege access to Rekognition `CreateFaceLivenessSession`, `GetFaceLivenessSessionResults` and `CompareFaces`. The Cognito Identity Pool role is only for the browser-side liveness stream used by AWS Amplify; Firebase remains the AutoFace account/authentication system.

## Thresholds
Defaults are deliberately conservative starting values, not validated production thresholds:

- `AUTOFACE_FACE_LIVENESS_THRESHOLD=90`
- `AUTOFACE_FACE_MATCH_THRESHOLD=90`

Benchmark genuine matches, deliberate mismatches, lighting, eyewear, ageing and device variation before production use.
