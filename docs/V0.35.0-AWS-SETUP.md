# AutoFace v0.35.0 — AWS Rekognition setup

This release keeps Firebase Authentication and Firestore as the AutoFace account system. AWS is used only for the live face check and one-to-one profile-photo comparison.

## 1. Choose one AWS region
Use the same region everywhere. For UK development, `eu-west-1` is a sensible default if Face Liveness is available for your account in that region.

Set in Vercel/local environment:

```text
AWS_REGION=eu-west-1
NEXT_PUBLIC_AWS_REGION=eu-west-1
```

## 2. Create the server IAM identity
For the v0.35.0 POC, the server needs only these Rekognition actions:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "rekognition:CreateFaceLivenessSession",
        "rekognition:GetFaceLivenessSessionResults",
        "rekognition:CompareFaces"
      ],
      "Resource": "*"
    }
  ]
}
```

Create credentials for this server identity and add them to Vercel as server-only environment variables:

```text
AWS_ACCESS_KEY_ID=...
AWS_SECRET_ACCESS_KEY=...
```

Never prefix these credentials with `NEXT_PUBLIC_` and never put them in source control.

## 3. Create a Cognito Identity Pool for the camera stream
The AWS Amplify Face Liveness browser component needs temporary AWS credentials to sign the liveness stream. This does **not** replace Firebase login.

Create a Cognito Identity Pool that allows guest/unauthenticated identities for this POC. Give its unauthenticated role only:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "rekognition:StartFaceLivenessSession",
      "Resource": "*"
    }
  ]
}
```

Add the Identity Pool ID:

```text
NEXT_PUBLIC_AWS_COGNITO_IDENTITY_POOL_ID=eu-west-1:xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

For a later production hardening pass, replace broad guest access with a short-lived credentials broker tied to the authenticated Firebase user/session.

## 4. Thresholds
The release ships with starting values only:

```text
AUTOFACE_FACE_LIVENESS_THRESHOLD=90
AUTOFACE_FACE_MATCH_THRESHOLD=90
```

Do not treat these as validated production thresholds. Test genuine users, mismatches, different lighting, glasses, older photographs and different phones before production release.

## 5. Install and run

```powershell
npm install
npm run build
npm run dev
```

Open:

```text
http://localhost:3000/verify-face
```

A profile photo must already exist before the face-verification session can start.
