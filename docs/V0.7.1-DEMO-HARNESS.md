# AutoFace v0.7.1 — Demo/Test Harness

v0.7.1 adds a repeatable development-only seed harness for Discovery and Mutual Introduction testing.

## What it creates

`npm run seed:demo` creates or refreshes three Firebase Authentication users and their supporting Firestore records:

- Priya — Leeds — 75% authenticity
- Maya — Manchester — 75% authenticity
- Alisha — Birmingham — 75% authenticity

Each account has:

- email marked verified;
- a development phone number;
- identity + liveness verification evidence;
- a completed AutoFace profile with `future_matches` visibility;
- a completed Atlas relationship profile;
- compatibility consent enabled;
- a server-owned `TEST PROFILE` marker.

The seed also resets interests and matches involving these demo users so repeated test runs begin from a known state.

## Production guardrail

The seed refuses to run unless the Firebase Admin project ID clearly contains `dev`, `test`, `demo`, `local`, or `staging`. It also refuses when `VERCEL_ENV=production` or `NODE_ENV=production`.

This is a development utility. Never weaken this guardrail to seed production.

## Commands

```powershell
npm run seed:demo
```

Optional cleanup:

```powershell
npm run seed:demo:clean
```

All demo accounts use the password in `AUTOFACE_DEMO_PASSWORD`. If the variable is blank or absent, the development default is `AutoFaceDemo!731`.

## Security boundary

The browser cannot write `identity`, `demoProfiles`, `interests`, or `matches`. The seed uses Firebase Admin credentials locally and the normal v0.7 Discovery APIs still expose only safe profile projections.
