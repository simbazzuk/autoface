# AutoFace v0.36.1.8.4 - Notification Chat Lifecycle Routing

Adds a canonical notification-to-chat routing layer.

## Why
A notification can outlive the exact state that existed when it was created. A match may now be active, message-limited, ended, blocked or unavailable.

## New route
`/notification-chat/[matchId]`

When a chat notification is clicked, AutoFace now checks the current server-side conversation state before opening the canonical `/messages/[matchId]` lifecycle page.

## Behaviour
- Active chat -> opens existing chat.
- Free allowance exhausted -> opens the same chat with current entitlement lock.
- Inactive/ended introduction -> opens read-only conversation history.
- Blocked/deleted/stale target -> opens privacy-safe unavailable state.
- Authentication is required before resolving the notification.
- Existing raw notification links are migrated where they are defined in notification-related TS/TSX/JS files.

No conversation is reactivated and no block is bypassed.
